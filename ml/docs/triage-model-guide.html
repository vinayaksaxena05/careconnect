Triage Model Field Guide

How to use triage_model_v1 from every seat: the triage nurse reading the prediction, the developer calling the endpoint, the ML engineer retraining it, and the operator holding the feature flags. For the how and why of the model itself, see the companion technical report.

The one rule

This model is clinical decision support. It never assigns a triage level. Every prediction is returned with requires_human_review = true and a clinical notice, and a clinician reviews and can override it. Nothing downstream acts on the model’s number — only the ESI a human records moves a patient.

1 · For clinicians

At the triage screen

Open Triage support from the main navigation. The screen is an assessment form followed by a model prediction you can accept or override.

Enter the assessment

  • Always required: age, sex, arrival mode, and the chief complaint in free text (“central chest pain”, “ankle sprain”).
  • Vitals: heart rate, respiratory rate, systolic & diastolic BP, oxygen saturation, temperature (°C). At least 3 of these 6 are required — the form will not offer a prediction from a near-empty assessment.
  • Pain is a 0–10 score, optional.
  • Values outside a physiological range are rejected on the spot, not silently corrected.

Press Predict triage.

  • ESI number, band, and name — the suggested level and its standard label.
  • Confidence is just the probability of the top level. It is not a calibrated likelihood; treat 0.55 and 0.85 as “less” and “more” sure, nothing more precise.
  • Per-level probabilities show where the model’s remaining doubt sits — a 2 with mass on 1 is different from a 2 with mass on 3.
  • Why lists up to five drivers, each marked as pushing toward higher acuity or lower acuity. This describes the model’s weighting, not clinical truth.

Record your decision

Accept keeps the model’s level as your final ESI. Override lets you set a different level and give a reason. Either way a separate Final clinical triage panel then shows the level that counts. Both values — model and human — are stored; your override is never discarded.

If it says “unavailable” A 503 or “prediction unavailable” message means the model is disabled or not loaded. Nothing is broken — continue with standard manual triage. The rest of CareConnect is unaffected.
Known weak spot On the current synthetic model, a predicted ESI 4 is unreliable (recall 0.25 — it often belongs at 3 or 5). Give “4” predictions extra scrutiny. See the technical report, §7.

2 · For developers

The API

Base path /api/emergency/triage. All routes require authentication. Predictions are per-caller; list and fetch only return the authenticated user’s rows.

Request — POST /predict

// TriageInput — the one validated feature contract

  "pain_level": 7

// vitals are optional individually — but >= 3 of the 6 core

}

Persist & override semantics

  • POST / with features only — stores the prediction, requires_human_review = true, no human ESI yet.
  • POST / with human_final_esi — the Accept / Override path. was_overridden is set to human_final_esi != predicted_esi.
  • PATCH /{id} with human_final_esi (+ optional override_reason) — records the decision later. The model columns are never modified; both values persist side by side.

4 · For ML engineers

Retrain & evaluate

Training and evaluation dependencies are separate from the backend runtime set:

pip install -r ml/requirements.txt

Regenerate the shipped demo model (synthetic)

python -m ml.training.train --source synthetic --n-samples 16000 --model-version v1 --force

Runs load → clean → stratified 60/20/20 split → fit preprocessing on train only → train the zoo × {structured, +TF‑IDF} → select on validation macro‑F1 (high‑acuity recall tie‑break) → refit the winner on train+val → score the test split → serialize. Writes the .joblib, a .metadata.json, a .metrics.json, and updates models/latest.json. Refuses to overwrite an existing version without --force.

--text-mode: compare (default — evaluate both and pick), on, or off.

Train against MIMIC‑IV‑ED

Unpack a credentialed copy so the ed CSVs sit together:

ml/data/mimic-iv-ed/
  edstays.csv.gz
  triage.csv.gz
  patients.csv.gz     # optional (MIMIC-IV hosp) — enables `age`
python -m ml.training.train --source mimic --data-dir ml/data/mimic-iv-ed --model-version v2

Only the triage row and arrival columns of edstays are read. No dataset is ever committed.

Score a saved artifact

python -m ml.training.evaluate --model ml/models/triage_model_v2.joblib --source mimic --data-dir ml/data/mimic-iv-ed --out ml/models/triage_model_v2.metrics.json

Tests

pytest ml/tests backend/tests

Covers preprocessing, both predictors, the evaluator, the explainer, and the API contract.

5 · For ML engineers

Replace the model

The API and UI depend only on ml.inference.TriagePredictor and the response contract. To swap the estimator (say LightGBM) or the text representation (embeddings instead of TF‑IDF):

  1. Keep the Pipeline(FeatureEngineer → transform → estimator) shape, or implement a new TriagePredictor subclass in ml/inference/predictor.py.
  2. Produce a joblib artifact of {"pipeline": <estimator with predict_proba>, "metadata": {…}} with the same metadata keys (model_name, model_version, features, uses_text, metrics, disclaimer, …).
  3. Bump --model-version. No FastAPI or frontend change is required.

Artifact format

joblib.dump(
  { "pipeline": <sklearn Pipeline: FeatureEngineer → ColumnTransformer → estimator>,
    "metadata": { "model_name", "model_version", "training_dataset",
                   "target", "features", "uses_text", "random_seed",
                   "n_train"/"n_val"/"n_test", "library_versions",
                   "metrics", "nlp_comparison", "model_comparison",
                   "disclaimer" } },
  "ml/models/triage_model_vN.joblib")

The loader also tolerates a bare pipeline, but a well-formed artifact carries metadata. The pipeline must expose predict and predict_proba.

6 · For operators

Config & feature flags

All four are read from the environment by backend/app/config.py.

Environment variables
VariableDefaultEffect
TRIAGE_ML_ENABLEDtrueMaster switch. Falsey → every /triage/* endpoint returns 503; the rest of CareConnect is untouched.
TRIAGE_MODEL_BACKENDautoauto: load the artifact if possible, else the rule-based fallback. model: require the artifact, fail loudly (ERROR log) if missing. heuristic: always the rule-based predictor.
TRIAGE_MODEL_PATH(empty)Explicit .joblib. Empty → models/latest.json → newest triage_model_*.joblib.
TRIAGE_MODEL_VERSION(empty)Informational only; surfaced in /health. The loaded artifact’s own metadata is authoritative.
Switching versions Point TRIAGE_MODEL_PATH at the new file (or let training’s models/latest.json do it) and restart the API. The model is loaded once at startup and held in memory; it is not hot-reloaded.

7 · For operators

Health & failure modes

The predictor is built once in the FastAPI lifespan startup and held by a process-wide TriageService. A missing or corrupt artifact never crashes the app. With backend=model the failure is logged at ERROR; otherwise at WARNING; either way the endpoints return 503 and manual triage continues. Raw patient payloads are never logged — only the failure class.

GET /health

{ "enabled": true, "status": "ready", "backend": "auto",
  "configured_version": null,
  "model_name": "xgboost", "model_version": "v1",
  "model_type": "ml", "uses_text": true }
status values
ValueMeaning
readyA predictor is loaded and serving.
disabledTRIAGE_ML_ENABLED is falsey, or build_predictor returned nothing. Endpoints 503.
errorInitialisation threw. error field carries the exception class + message. Endpoints 503.
uninitialisedStartup has not run (or shutdown did). Transient.

model_type tells you which predictor answered: ml (the artifact) or heuristic (the rule-based fallback, rule-based-esi / heuristic-v0 — coarse vital-sign thresholds and chief-complaint keywords, deterministic, explicitly not machine learning).

8 · For operators

The prediction store

Migration: supabase/migrations/20260901000000_triage_predictions.sql. Until it is applied, predictions still work — POST / returns 503 with “prediction still works; it was not saved”. The table has RLS policies mirroring the other patient-owned tables and indexes on user_id, emergency_id, and created_at.

triage_predictions — columns
ColumnMeaning
predicted_esi, prediction_probabilities, confidence, explanationModel output — immutable. Never rewritten by the human decision.
model_name, model_version, model_typeWhich predictor produced it.
input_featuresThe exact inputs the prediction was made from — audit & reproducibility.
human_final_esiThe clinician’s decision (may equal or differ from the model).
was_overriddenSet to human_final_esi != predicted_esi.
override_reason, reviewed_byRationale and who recorded it.
requires_human_reviewAlways true on insert.

From the admin console only the human-review fields are editable (human_final_esi, was_overridden, override_reason, requires_human_review); the model output columns are read-only there too. The side-by-side record exists so that model accuracy and any drift toward rubber-stamping the model can be audited after the fact.
